# Security model

## Assets and threats

Assets: the user's imported correspondence (their own words and other people's), the SQLite database, provider credentials and mailbox sign-ins, the updater trust root.

Threats considered: a runaway or crashing sidecar; a malformed or hostile export file; a compromised update channel; message content escaping into logs, diagnostics or an error string; a credential leaking into the database or a bundle; a provider that is not what it claims to be; another program on the computer answering, or intercepting, a sign-in's return from the browser.

Not in scope, and stated rather than implied: another program running as the same user, and an administrator of the computer. On Windows, provider credentials, mailbox app passwords and a Microsoft mailbox's sign-in (its refresh token) are sealed to the user's account with DPAPI, so a copied, backed-up or synced file, or the disk read by another account, is no use without the user's Windows password — but any process with this user's rights can ask Windows to unseal them, as it can the browser's saved passwords, and an administrator can reach them too. See `docs/MODEL_PROVIDERS.md`.

## Controls

| Area            | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Network         | No inbound listener, except while a Microsoft sign-in waits on the browser: then, for at most five minutes, one on the loopback addresses only (`127.0.0.1`, and `::1` on the same port), on a port the system picks, which reads one request per connection for at most five seconds, answers only the request carrying the sign-in's `state`, and closes when that arrives. Outbound: the update check, whatever the selected model provider requires, and — only once the user connects one — their own IMAP server, and for a Microsoft mailbox Microsoft's sign-in service (`login.microsoftonline.com`, over TLS), to sign in and to trade the kept sign-in for an access token. IMAP is implicit TLS verified against the bundled Mozilla roots (`webpki-roots`); a plain connection is refused before connecting unless the host is loopback, so an app password is never offered in the clear to a remote server. The default provider is loopback-only. |
| Mailbox access  | Read-only by construction: the IMAP client has no command that writes (`EXAMINE` rather than `SELECT`, `BODY.PEEK[]`, no `STORE`/`EXPUNGE`/`APPEND`/`COPY`/`MOVE`), and the tests assert none is ever sent. A Microsoft mailbox signs in with `AUTHENTICATE XOAUTH2` and an access token, answers a challenge with an empty line as the mechanism requires, and never sends a password. A username, password or folder containing CR or LF is refused rather than allowed to end a command early. A server's reply text reaches an error message only as one line of at most 160 characters. Messages over 25 MiB are skipped by their reported size without being fetched, and one command's reply is capped at 64 MiB.                                                                                                                                                                                                                                          |
| Sign-in         | The OAuth 2.0 authorization code flow for native apps (RFC 8252) in the user's own browser, on the provider's own page, so Mimic never sees the password. PKCE `S256` (RFC 7636) with a 32-byte verifier from a cryptographically secure generator seeded by the operating system (`rand`'s thread generator), which never leaves the process except to the token endpoint, and a 16-byte random `state`; a code whose `state` is not this sign-in's is refused and waited past. Mimic is a public client: no client secret, and the client id, compiled in, is not treated as one. One sign-in at a time, stoppable, given up after five minutes. Access tokens are held in memory only and renewed five minutes before they lapse; a changed or removed sign-in waits for any renewal in progress, so a renewal cannot write back over it. `Tokens` and `Pkce` print as redacted; the provider's error text reaches the screen as one line.                     |
| Engine          | Spawned via argument array with `kill_on_drop`; NDJSON only; 32 MiB per-message cap in both directions with a restart on violation; a restart budget of 5, then manual; every handler exception becomes a structured error; no `eval`, no shell.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Imports         | Read-only. An export file is never modified or moved. A malformed file produces a `source_malformed` error, not a panic; the connector tests include truncated JSON and headerless mail.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Files           | Everything Mimic writes is under the per-user app data directory. The `credentials/` directory is `0700` and the file inside it `0600` on Unix; `%LOCALAPPDATA%` is already per-user ACL'd on Windows. The credentials file is replaced in one step (write, flush, rename), never rewritten in place.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Database        | Per-user app data; migrations transactional with a pre-migration backup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Credentials     | API keys, app passwords and a Microsoft mailbox's refresh token (under `imap:<source id>`, where its password would be) are sealed to the Windows account with DPAPI (current user, no prompt, Mimic's own entropy) before they are written; never written unsealed on Windows, even when sealing fails. Never in the database, never in settings, never in a log. Providers receive them through `SecretStore`. Diagnostics strip `token`, `apiKey`, `api_key`, `password` and `secret` at every depth.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Message content | Never logged by default. Provider errors are truncated to one line and carry the provider's status and message, never the request body. The diagnostics bundle contains counts and error events, never bodies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Webview         | CSP restricted to `self`, `ipc:` and inline styles. The Tauri asset protocol is disabled entirely — the app has no reason to load a file from disk into the webview.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Updater         | Tauri updater with signature verification against the public key embedded in `tauri.conf.json`; the private key exists only as `TAURI_SIGNING_PRIVATE_KEY` in GitHub Actions; the release workflow refuses to build without it and refuses the development public key for non-alpha tags; installs never interrupt active jobs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Models          | Encoder manifests are SHA-256 pinned; a manifest missing `id`, `url`, `sha256` or `dims` is refused. The lexical fallback needs no download.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Supply chain    | Lockfiles committed; `cargo audit` and `pnpm audit` in CI (warning level in 0.x); a secret scan on every push.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Known gaps

- A program running as the user, or an administrator, can unseal saved credentials (see above). Builds other than Windows write them unsealed to an owner-only file and say so; the Keychain / Secret Service arrive with macOS (`docs/ROADMAP.md`).
- Versions before 0.10.0-alpha.6 kept credentials unsealed in `credentials.json`. Moving them in deletes that file but does not erase it, so a key or app password saved before then may survive in backups or free disk space; replacing it is the way to be sure.
- No commercial code-signing certificate (SmartScreen warnings on first install); updater signatures still protect updates.
- The development updater key pair was generated during repository creation. Acceptable for alpha builds only; it must be rotated before a stable release (see `docs/RELEASE_PROCESS.md`).
- A hosted provider receives message content by design. The user chooses it, the top bar names it, and the Settings description says exactly what is transmitted — but Mimic has no way to verify what the provider does with it.
- Gmail, Yahoo and iCloud sign in with `LOGIN` and an app password; signing in with Google is not built.
- Mimic's Microsoft client id is Mimic's alone but, as for any app on a computer, not a secret (RFC 8252 §8.5): another program could present it. PKCE is what makes a code intercepted on its way back useless to anything but the process that asked for it. Another program running as the user could read the kept refresh token, as it can the app passwords (above).
- Removing a Microsoft mailbox deletes Mimic's copy of the sign-in but does not tell Microsoft; the user withdraws Mimic's access in their Microsoft account's app permissions. A build without the client id (`MIMIC_MICROSOFT_CLIENT_ID`) cannot sign in with Microsoft and says so.
