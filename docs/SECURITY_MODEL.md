# Security model

## Assets and threats

Assets: the photographer's library (read-only to Mimic), the Lightroom catalog (never touched directly), the local database, the updater trust root.

Threats considered: a local process or web page trying to drive the bridge; a malicious or corrupt sidecar/image; a compromised update channel; a runaway or crashing engine; path injection from plugin-supplied paths.

## Controls

| Area               | Control                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bridge             | Binds `127.0.0.1` on an OS-assigned port; 256-bit random token per launch (constant-time compare); discovery file written atomically with mode 0600 on Unix (per-user ACL'd `%LOCALAPPDATA%` on Windows); `Authorization: Bearer` required on every route including health; requests with an `Origin` header rejected (403); body limit 8 MiB (413); command queue bounded (256) with timeouts; late results for timed-out commands rejected (404). |
| Plugin             | Validates protocol version, loopback URL and token length from the discovery file; never sends pixels; uses only public SDK calls; snapshot failure aborts the apply for that photo.                                                                                                                                                                                                                                                                |
| Engine             | Spawned via argument array with `kill_on_drop`; NDJSON only; 32 MiB per-message cap (both directions) with restart on violation; restart budget of 5 then manual; every handler exception becomes a structured error; no `eval`, no shell.                                                                                                                                                                                                          |
| Files              | Source media opened read-only; sidecars read-only; paths from the plugin are only used to `stat`/read, never to write; preview/embedding caches under app data only.                                                                                                                                                                                                                                                                                |
| Database           | Per-user app data; migrations transactional with pre-migration backup.                                                                                                                                                                                                                                                                                                                                                                              |
| Updater            | Tauri updater with signature verification against the public key embedded in `tauri.conf.json`; private key exists only as `TAURI_SIGNING_PRIVATE_KEY` in GitHub Actions; release workflow refuses to build without it and refuses the development public key for non-alpha tags; installs never interrupt active jobs.                                                                                                                             |
| Models             | Manifest-pinned SHA-256; atomic rename after verification; fallback to `stats_v1` when absent or mismatched.                                                                                                                                                                                                                                                                                                                                        |
| Logs / diagnostics | No tokens; paths redacted by default; no pixel data.                                                                                                                                                                                                                                                                                                                                                                                                |
| Supply chain       | Lockfiles committed; `cargo audit` and `pnpm audit` in CI (warning level in 0.x); secret scan on every push.                                                                                                                                                                                                                                                                                                                                        |

## Known gaps

- No commercial code-signing certificate yet (SmartScreen warnings on first install); updater signatures still protect updates.
- The development updater key pair was generated during repository creation. It is acceptable for alpha builds only and must be rotated before 0.1.0 stable (see RELEASE_PROCESS.md).
