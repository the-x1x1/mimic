# CLAUDE.md — agent entry point for Mimic

You are working on Mimic, a local-first Windows desktop app that learns how a person communicates and helps them draft responses that sound like themselves. Read this file first, then `docs/PROJECT_STATUS.md`, then the code you are about to change.

Mimic was a Lightroom Classic editing assistant through 0.5.0. It is not any more. `docs/MIGRATION_AUDIT.md` records what happened; `archive/legacy-photography/` holds what was worth keeping. Nothing in the archive is built, tested or shipped, and nothing in the live tree should refer to it.

## Source of truth (highest first)

1. Source code
2. Automated tests (`cargo test`, `pytest`, `vitest`)
3. Reproducible runtime evidence (logs, diagnostic bundles, fixtures)
4. GitHub release artifacts
5. `docs/PROJECT_STATUS.md`
6. `docs/ROADMAP.md` and the rest of `docs/`

Documentation follows reality. Never let a doc lead the code.

## Non-negotiable rules

- **Never** treat a message as evidence of how the user writes unless its `direction` is `self`. Received messages are context; they are never a voice metric, a representative example or a retrieval result.
- **Never** show a number that was not measured. A rate that has not been computed is `None` / `null` / "not measured yet". `0` means measured zero. The distinction must survive from the Rust struct through the zod schema to the rendered sentence.
- **Never** show an accuracy or quality score without a row in `evaluations` behind it and a definition in `docs/VOICE_ENGINE.md`. There is no "Mimic Score".
- **Never** infer a relationship, a tone or a situation and present it as a fact the user stated. `participants.relationship` is set by hand and by nothing else.
- **Never** let message content reach a log, a diagnostics bundle, or a provider error string.
- **Never** put a credential in the database or in settings. Providers read them through `SecretStore`.
- **Never** claim a provider is local. Compute it from the endpoint (`LocalHttpProvider::is_loopback`) and let the answer be what it is.
- **Never** add a send path. Mimic drafts; the user sends. Trusted Mode is designed and deliberately unbuilt.
- **Never** write to a mailbox. The IMAP client reads with `EXAMINE` and `BODY.PEEK[]` and has no command that changes anything; the tests fail if one is sent.
- **Never** delete a person without removing what was derived from them and invalidating what was computed over them. The preview must be produced by the same code path as the deletion.
- **Never** drop the user's own words during normalization when a line's role is ambiguous. Keeping a stray quoted line is a smaller error than deleting a real one.
- **Always** add a new numbered migration for a schema change (`crates/mimic-core/src/db/migrations/`), never edit a shipped one, and extend the migration test.
- **Always** give a shared contract a checked-in fixture parsed by both Rust and zod.
- **Always** update `docs/PROJECT_STATUS.md` in the same commit as the behaviour it describes.
- **Always** test version changes (`node scripts/sync-version.mjs --check`, part of `test.ps1` and CI).
- The UI must hide or disable what does not work and say why. No buttons that pretend, no sample numbers shown as real metrics.

0.10.0-alpha.14 signs in to Outlook.com, Hotmail and Microsoft 365 mailboxes with Microsoft. `sources::oauth` is the RFC 8252 flow: `sign_in` binds a `Loopback` (127.0.0.1 on a port the system picks, and ::1 on the same port when it can), opens `authorization_url` (PKCE `S256` from `Pkce::new`, a random `state`, `login_hint`) in the user's browser through the caller's `open`, waits up to `SIGN_IN_WINDOW` (five minutes) or until `should_stop` for the request carrying its `state`, reading every connection at once without blocking on any (a silent one is dropped after five seconds) — anything else gets a 400 or 404 and is waited past, and the provider's `error` ends the wait as `Denied` — and exchanges the code (`exchange_code`); `refresh` trades a refresh token for new tokens, with `invalid_grant`, `interaction_required` and `consent_required` read as `SignInAgain`. `Provider::microsoft()` has the `common` endpoints, the scope `https://outlook.office.com/IMAP.AccessAsUser.All offline_access` and `outlook.office365.com:993`; the client id is `option_env!("MIMIC_MICROSOFT_CLIENT_ID")` (`microsoft_client_id`), from the repository variable in the release workflow, and a build without it says so and offers nothing. `ImapAccount.auth` is `password` (the default, so every existing config reads unchanged) or `microsoft`; `Connection::open`, `probe` and `sync` take a `Credential` (`Password` or `AccessToken`, both redacted in `Debug`), and an access token signs in with `AUTHENTICATE XOAUTH2` (`oauth::xoauth2`), answering a challenge with an empty line; a refusal is `ImapError::SignIn`. `imap::Credentials` (in `AppState.mail_credentials`, shared with `CheckMailboxExecutor`) gives each check its credential: the password, or an access token kept in memory until five minutes before it lapses and otherwise refreshed from the refresh token stored under `imap:<source id>`, saving the one handed back; `forget` drops a token the server turned down, and `settle` makes a change to the stored sign-in (a new one, or removing it with the mailbox) wait for a refresh in progress, so it can't be written over. The desktop commands are `mail_sign_in_available`, `sign_in_to_mailbox` (sign in and probe, one at a time — `AppState.sign_in`, held by a `SigningIn` until the command returns and the wait on the browser ends — holding the result in memory, and nothing if stopped), `connect_signed_in_mailbox`, `cancel_mail_sign_in` and `sign_in_mailbox_again` (probe first, then keep). `KNOWN_MAIL_HOSTS` marks outlook.com, hotmail.com, live.com and msn.com `signIn: "microsoft"`, and `guessMailHost` gives the same to Microsoft's domains in other countries (`MICROSOFT_ELSEWHERE`, named one by one — hotmail.co.uk, outlook.fr, live.com.au — since a pattern would take in other people's domains, live.io or outlook.co, and leave them no password field); the password commands always store `auth: password`; `ConnectMailboxDialog` asks those, and work accounts ticked under Server settings, for no password; `MailboxSignInAgain` is under Your mail for a Microsoft mailbox. `replace_password` refuses a Microsoft mailbox.

0.10.0-alpha.11 measures the drafts (`crate::evaluation`, docs/VOICE_ENGINE.md "Measuring"). `Db::evaluation_exchanges` lists every (someone else's non-automated message, the user's reply straight after it), newest first; the engine's `eval.split` splits them by conversation; `choose` takes up to `MAX_CASES` (12) held-out exchanges, the newest of each conversation first. `write_answers` answers each twice with the active provider — Mimic's own prompt, through `generation::build_context_holding_out` with a `HeldOut` (the held-out conversations excluded from retrieval by `RetrievalFilter::exclude_conversations`, a `json_each` parameter; the transcript cut before the incoming message by `Db::messages_before`; the voice measured again without the held-out conversations by `voice::LeavingOut`, each scope once per run; learned habits left out) — and a generic prompt with the same messages and none of the user's measurements, examples or habits. `common_reply` is the reply sent most often in the training split. `eval.compare` measures all three against the actual reply; `Db::record_evaluation` writes one `evaluation_cases` row per answer (migration 0011: message ids with `ON DELETE CASCADE`, and nothing recorded when no case is left), and `evaluation::latest` works the figures out from the cases that remain and still read as someone else's message and the user's reply (mean and numpy-style 10th percentile per measure per system). Deleting any person or source deletes every evaluation (`privacy`, `DeletionReport.evaluations`). Nothing writes a draft. `Harness` abstracts the engine: `EngineHarness` in the app, `LocalHarness` (no encoder, so no `embedding`) in tests. The job is `evaluate_drafts` (`EvaluateExecutor`, not resumable, in `HOLDS_PEOPLE` so no fold runs under it), started by `start_evaluation` (refused while the engine isn't ready or a run is queued) and shown by `HowClose` on the Voice page with no headline number. The engine client also stops being able to hang: a request's timeout covers writing it (in a task of its own, so a cancelled caller can't leave half a line), a line not written whole kills that engine — only that generation's, compared under the process lock — for the app to restart, and `stop` never waits on a write.

0.10.0-alpha.10 is the whole conversation. `Db::conversation_page(conversation, from_message, Toward::{Earlier, Later}, limit)` reads up to `limit` messages next to one message of a conversation, oldest first, as `ThreadMessage` (id, direction, author — never for the user's own — sent_at, body, the header reading `automated`) with `more`, the count still further that way. Order is `(sequence_index, id)`, the waiting list's own tie-break, and a page is keyed on the message at its far end, so pages never share or skip a message even where a batch left positions tied. `Db::place_in_conversation` counts both sides of a message; `dashboard::thread` puts them on every card as `earlier` / `later` — what is after the message on a card is what did not decide it (automated, or `unknown` direction), and is counted rather than hidden. `get_conversation_page` (limit clamped to 1..=200) serves `RestOfThread` in `RepliesPage.tsx`: one per side, closed by default, an infinite query under the `dashboard` key (so whatever refreshes the home screen refreshes it) that reads only once opened, twenty at a time.

0.10.0-alpha.9 is one Mimic at a time. Two processes on one database each ran the job queue: the second's start-up `recover_interrupted_jobs` marked the first's running jobs interrupted and queued them again, both could take the same queued job, and both wrote the credentials file. `tauri-plugin-single-instance` (registered first) hands a second launch to the running process, which shows and focuses its `main` window. Closing keeps the event loop running: `on_run_event` answers `RunEvent::ExitRequested { code: None }` (the last window closed) with `prevent_exit`, sets `CLOSING`, stops the engine on the async runtime — for at most `ENGINE_STOP_LIMIT` (5 s), since the kill can wait on a busy engine's writer — and then calls `exit(0)`, so a launch in those seconds still reaches `second_launch`, which sets `REOPEN`; `run` uses `run_return`, and once the loop has ended — and the plugin has released the hand-over on `RunEvent::Exit` — starts `current_exe()` again before exiting. An exit asked for in code passes straight through, stopping the engine on `RunEvent::Exit` if it is still running. `tauri_plugin_single_instance::destroy` is not called by hand: the plugin calls it on exit and 2.4.5's Windows `destroy` does not clear its handles, so a second call would close them twice. `mimic_core::instance::InstanceLock` is the backstop on the data itself: `startup::take_instance_lock` locks `data/mimic.lock` (`AppPaths::instance_lock_file`) with `File::try_lock` before the database is opened — waiting up to ten seconds (`InstanceLock::acquire_within`) for a Mimic that is still exiting — holds it in `AppState.instance`, and returns `instance::AlreadyRunning` when it is held, which `run` tells apart with `anyhow::Error::is`: it shows a native dialog and exits, having touched nothing. The `main` window is `"create": false` in `tauri.conf.json` and built in `setup` from its config once the lock is held, so a refused copy never shows one. The operating system releases the lock when the process ends, however it ends (`instance::tests::a_holder_that_is_killed_lets_go` kills a real holder). The workspace's `rust-version` is 1.89 for `File::try_lock`. A dev build shares the installed app's identifier, so `pnpm tauri dev` hands over to an installed Mimic that is running: close it first.

0.10.0-alpha.8 makes an address the user adds count for mail already read, without turning a real person into the user unasked. `repo_identity::owner_of` (through `person`) is the one query behind `Db::preview_user_address` (`AddressPreview`: whether it is already the user's, and the `AddressOwner` the mail is filed under — messages, other addresses, relationship, notes, relationship preferences), `Db::add_user_address(kind, value, confirmed)` and `Db::held_user_addresses`. `add_user_address` is one transaction and refuses with `DbError::Unconfirmed` (command code `confirm`) unless `confirmed` equals the `AddressOwner` that query finds now, so a yes to a question whose answer has since changed is refused and the UI asks again. The fold makes the owner's other addresses (not names) the user's, turns their messages to `self` with no participant, keeps drafts addressed to nobody, deletes their relationship profiles, examples and preferences and then the participant, relinks replies and recounts every conversation they were in, and marks every profile stale. `Db::claim_user_mail` folds only participants for whom `is_only_the_user` holds (every non-name identifier already the user's; no relationship, notes or relationship preferences — a hand-given name is not recorded, so it is not counted) and returns `Reconciled { claimed, left }`; the desktop's `reconcile_identity` runs it at start-up after job recovery, after `connect_mailbox` adds a mailbox's address, and after every job finishes (before its event reaches the screen, so a deferred fold gets another chance at each), logging `identity/reconciled` only when someone was folded. `Db::keep_apart` records a No on the person (`participants.kept_apart`, migration 0010, so it goes with them), which `claim_user_mail` respects; `Db::claim_held_address(identifier_id, confirmed)` settles a held address as stored. Folding refuses with `DbError::Busy` (code `busy`) while a job that holds people runs (`import_source`, `check_mailbox`, `analyze_voice`, `assist_drafts`), checked inside the transaction; a plain add refuses only while mail is being read; `create_draft` stores a participant that is gone by then as nobody. Core `add_user_identifier` now only inserts (matching kind as well as value) and is what tests and `connect_mailbox` use. The UI asks through `features/identity/AddAddressForm` (Settings, the identity step, and the import step's none-of-yours state) and `HeldAddressQuestion` for each held address under Settings → You (it sends the owner it showed when it opened, and shows a changed one with a note), both with `FoldConfirm`. Removing an address is not re-attributed, because the author address of a message is not stored.

0.10.0-alpha.7 is only what is still waiting. `db::repo_waiting` gains a third reason to leave an unanswered thread out, after the user's mark and the headers: its deciding message is older than the waiting window (`waiting.withinDays`, 30 days by default, 0 for any age), measured against the clock with `julianday`, and a message with no readable date is never old. It is counted (`LeftOut.quiet`), carried on the thread (`quiet`) and named with its window (`Dashboard.waitingWithinDays`); the user's `needs_reply` mark keeps an old thread on the list. Tests with fixed dates open the window to any age in their setup, because the clock moves; the window itself is tested with dates relative to now.

0.10.0-alpha.6 seals saved credentials to the user's Windows account: `secrets.rs` in the desktop crate writes each value through DPAPI (`CryptProtectData`, current user, no prompt, Mimic's own entropy) to `credentials/secrets.json`, and never writes unsealed when sealing fails. The unsealed `credentials.json` of earlier versions is moved in value by value — each not already dealt with, marked by a sealed hash of key and value only once it has been written and read back — and deleted only after that, so a value that opens is never lost with it and one changed or cleared since is not brought back, even by a restored copy; every save starts from the file on disk. A value that does not open here is kept and reported as locked, and an unreadable file is set aside or left alone, never overwritten. `ProviderState.credentials` carries what the store did, and the Privacy card and the mailbox dialog say only that. `sources::imap::replace_password` gives a connected mailbox its password again (login first; nothing imported is touched), behind **New password** under Your mail. 0.10.0-alpha.4 is only what needs a reply. `sources::automated` reads at import, from headers alone, whether a machine sent a message (list mail with nowhere to post, `Precedence: junk`, automatic replies, delivery reports, no-reply senders without an answerable `Reply-To`) and records why in `metadata.automated`; `db::repo_waiting` is the one definition of what is waiting, used by the home screen, its counts and assisted drafting alike. ## How to update PROJECT_STATUS

Each row has a status (`IMPLEMENTED | PARTIAL | PLANNED | UNSUPPORTED`) and an evidence column naming the test that proves it. When you change behaviour: change the row, point evidence at the real test, and move completed items out of `docs/ROADMAP.md`.

## Forbidden shortcuts

Fake success. Placeholder services. Empty interfaces "for bulk". God classes. Duplicated schemas without a checked-in contract. Unbounded workers. A metric computed in two places. A percentage with no computation behind it. Silent uploads. Treating a received message as the user's writing. Marking anything done without a test.

## Release protocol (owner's rules)

One coherent slice per version with code, tests and docs together; every shared contract gets a checked-in fixture; `test.ps1` green before claiming green; state plainly what could not run; the version bumped everywhere a version lives (`sync-version.mjs --check` enforces it); one clean commit per slice authored `the-x1x1 <connersalt123@outlook.com>`; and no AI attribution anywhere — not in a commit message, not in a PR description, not in release notes.
